# Domain docs

This is a single-context repository. Engineering skills consume its domain documentation as follows.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read decisions under `docs/adr/` that touch the area being changed when they exist.
- If either location does not exist yet, proceed silently. Producer workflows create domain terms and decisions lazily when they become concrete.

## Vocabulary

Use terms as defined in `CONTEXT.md` in issues, plans, tests, and implementation. Do not drift to synonyms the glossary explicitly avoids. A missing term may indicate either invented language or a genuine domain gap to resolve.

## Architectural decisions

If proposed work contradicts an existing ADR, identify that conflict explicitly and explain why reopening the decision may be warranted.
