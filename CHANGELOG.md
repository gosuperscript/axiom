## [Unreleased]

### Added
- **Compilation that reports everything wrong, not just the first thing.** `Expression::diagnose(): Diagnosis` compiles for the sake of what compilation learns: every refusal in the expression, the symbols it read even through the parts that refuse, the root type, and — when nothing refused — the certified `Program`, through `Diagnosis::program(): Result<Program, non-empty-list<TypeMismatch>>`. `mystery > 1000 && postcode == 'SW1'` with `mystery` undeclared reports one diagnostic (the unbound symbol), still type-checks the right-hand comparison, and still reports `['mystery', 'postcode']` as references — where `compile()` reports the unbound symbol and stops. `compile()` is one attempt of the same walk and behaves exactly as before: its refusal is the diagnosis' first diagnostic, same message, same path. Nothing to migrate.
  - **One fault produces one diagnostic.** A node that refuses compiles to a *failed* `CompiledSource` — the second of the two states one comes in, carrying no type and no evaluation — and every judgment about a child's type absorbs one rather than refusing on it: an operation over it resolves with no rule lookup, an ascription over it claims nothing, a member access on it certifies nothing. Host source compilers judge through the same capability — `SourceCompilation::overlaps()`, `shapeOf()`, `infix()`, `prefix()` all absorb before asking — so absorption is machinery rather than something to remember; `SourceCompilation::absorb()` and `CompiledSource::failed()` cover a judgment the capability cannot make for you. A refusal that survives absorption is a fault of its own, and is reported.
  - **Diagnostics converge.** A refusal a failed source answers for is not reported, so fixing one fault can reveal the next: a non-exhaustive match over an unbound subject reports only the unbound subject, because until it is declared the subject is `Never` and any set of patterns covers it. Declaring the subject surfaces the missing wildcard.
  - **Failure is a compilation state, not a type.** `Analysis\CompilationState` records what became of each source — Certified, Failed or Abandoned — and a failed compiled source carries no type and no evaluation: `CompiledSource::$returns` throws on one, and `Diagnosis::$returns` is `null` for an expression whose root itself failed. There is no marker for a host to be handed, wrap in a composite of its own, or claim back, so the types a host authors are never inspected. `Program`'s constructor refuses any node tree in which something failed, at the cost of one boolean read carried bottom-up by the compilation node.
  - **A compilation node is certified, failed or abandoned**, on `CompilationNode::$state`. A certified node carries the type it returns and the extension whose compiler owns it. A failed one is a source the compiler gave up on; it claims neither, and never reaches an analysis, because an analysis is built only for a certified program. An abandoned one stands where a child refused and its compiler caught the refusal and compiled without it — the position exists so paths stay stable across the compilations `diagnose()` makes, and it too claims neither type nor compiler: reading `$returns` or `$extension` throws, and `toArray()` renders `['path' => …, 'source' => …, 'abandoned' => true]`. It is never a failure and never blocks certification.
- **Compiled programs report their input reads.** `Program::$references` lists the declared input keys resolved by successful compilation, including reads reached through definitions, in first-read order without duplicates. Consumers can reuse this compiler-produced fact instead of maintaining a second source-tree walk.
- **Separately-bound source bodies compile once and run many times.** A host source can persist a `Subexpression` with explicit parameter names, compile it through `SourceCompilation::subprogram()` using types certified from sibling sources, and invoke the resulting `CompiledSubprogram` through `SourceEvaluation::invoke()`. Each call gets a fresh isolated runtime with exact bindings and the enclosing observer; it cannot implicitly capture program inputs or definitions. Bound parameters stay out of public input and definition analysis, while genuinely free symbols remain visible. This gives iterators such as host-owned `any` sources typed, short-circuiting predicate evaluation without adding callbacks or a generic lambda source to the persisted language.
- RFC 0001: Typesafe Axiom (`docs/rfc/0001-typesafe-axiom.md`) — the design record for the statically typed, compiled expression language, shipping as one breaking release; `docs/extending-axiom.md` is the extension guide.
- **Compilation**: `Expression::compile(): Result<Program, TypeMismatch>` type-checks a program once — cycles, unbound symbols, unresolvable or ambiguous operators, dead comparisons, non-exhaustive matches, false ascriptions all refuse with named diagnostics — and returns a certified, callable `Program` (`$program->returns` is the inferred type; `$program($bindings)` runs the boundary and then evaluates). A compiled program embeds its operator resolutions and performs **no runtime type dispatch**; definitions compile once and evaluate lazily, memoized per invocation (`Runtime`). `Expression::infer()`/`check()` are conveniences over `compile()`.
- Invocation-scoped execution observation: `Program::call()` accepts an optional `Execution\Observer`; every compiled source node emits ordered `Entered`, `Annotated`, `Exited`, or `Threw` events carrying its source class and certified return type. Observers are never stored on persistable sources or retained by programs, while host source compilers participate automatically through `CompiledSource` composition and may add domain annotations through `SourceEvaluation`.
- The sealed shape algebra (`Types\Shapes`): `Boolean`/`Number`/`String`, `Literal`, `Option` (value-set semantics, nesting collapses), `Union` (canonicalized), `Record` (exact named fields), `Dict`, `List` (validated length bounds), `Unknown`, `Never`, `Opaque` (nominal head with structural parameters). Shapes are **census-verified truth claims** about runtime structure: fictional record projections for object-valued types (the TypeScript branded-types trick) are outlawed — object domain types project `Opaque`.
- Type relations (`TypeRelations`): assignability (⊆ over value sets), equivalence, symmetric overlap (complete: a `dead` verdict is a constant-`false` claim, so one shared value — `[] == []` across list/dict/record — keeps a comparison live), pessimistic operand admissibility, and joint admissibility (the row-ambiguity relation: could some *operand type* be admitted by both slots? — distinct from overlap exactly where a shared value is not a shared type), with `TypeMismatch` cause chains rendered through `TypeDescriber`. There is deliberately no orderability oracle: whether `<` is meaningful for a type is answered by the dialect's ordering rows and nothing else.
- New language-level types: `OptionType` (null coerces to a present `Some(null)`), `LiteralType`, `UnionType`, `RecordType` (coercion canonicalizes missing optional keys to null), `UnknownType`, `NeverType`; `ListType` gains length bounds; every core type projects via `Type extends Shaped`, and hosts declare object-valued inputs with their own `Shaped` domain types (a real membership check + an `OpaqueShape` projection).
- Typed operators, explicit verdicts: `BinaryOperatorRule`/`UnaryOperatorRule` each own one symbol and return a `ResolvedOperation`, `UnsupportedOperation`, or `DeadOperation` directly from `resolve(operand types)`. A success carries the return type *and* evaluation, so rule selection and evaluation are one statement and cannot drift apart (that the evaluation honors its stated type is the author's certified obligation, tested by the totality harness). Compiler-facing resolvers index rules by symbol and aggregate refusals without registration precedence. Core arithmetic, ordering, and logic are dialect rows; `Equality`, membership (`has`/`in`), and intersection are hand-written type functions that establish `ValueEquality` support before using overlap for liveness.
- The operator builder — the front door for extension operators: `Operator::infix('-')->takes(new DateType(), new PeriodType())->returns(new DateType())->evaluatesWith(fn (Date $d, Period $p) => $d->minus($p))` declares a fixed row, while `matching(TypeClass::class, ...)->resolvesWith(...)` gives computed rules typed class guards and explicit `Operation` verdicts. Resolution checks admissibility against the declared types and returns the return type with the evaluation, whose native parameters are safe because the compiler proved them. Closures auto-wrap plain values in `Ok`, pass a returned `Result` through, and let throws propagate; `Operator::prefix` rejects `Option` operand rows loudly. The raw rule interfaces remain the documented escape hatch for fully structural judgments.
- `Dialect` + `Extension`: operator rules, the literal registry, and exact-class source compilers — the core language's and a host's alike — live in one value object consumed at compile time; the program embeds what the dialect resolved, so checking with different rules than you run is unrepresentable. **Ambiguity is refused, never ranked**: two rows for one operator with jointly admissible slots (some operand type would resolve both — a `List` row beside a `Dict` row is a legal pair; a `Literal(5)` row beside a `Number` row is not) are a `Dialect` construction error; multiple rules resolving the same node are a compile error naming both. List order decides nothing. Duplicate literal and source compiler registrations stay loud errors.
- The compiler (`TypeInference`): literal-first inference, union element unification with exact list bounds, mandatory match exhaustiveness (`Never` vacuously covered; expression patterns compile like any program but never count toward coverage), shape-driven member access with reification (`TypeReifier`), optionality propagation, and `check` = infer + assignability. `TypeEnvironment` compiles symbols from declarations (boundary reads) and definitions (memoized slots); `LiteralTypeRegistry` types object literals. Every node compiles through the dialect's exact-class source compiler map: core registers its map through `Dialect::core()`, hosts through `Extension::sourceCompilers()`. A source compiler receives its source and a straight-line `SourceCompilation` capability and returns a `CompiledSource`; `child()`/`children()` compile persisted children, `mapPresent()`/`mapIncludingAbsent()` compose their values with explicit absence semantics, `infix()`/`prefix()` bind dialect operations, and `custom()` provides restricted lazy evaluation without exposing `CompiledNode`, `Runtime`, or `Result<Option<...>>`. Host `Source` objects remain serializable data descriptions; live collaborators stay in the extension and are captured only in the compiled program.
- Typed bindings: `Expression` accepts `declarations` and a `Boundary` mode (`Coerce`/`Assert`); the inputs the compiled program *reads* are validated/converted per call with aggregated, named `BoundaryViolation`s, and every other binding key is stripped. Declarations are the vocabulary the program is typed against; `Program::$references` is the slice of it the program actually reads, and so its runtime signature (see *The boundary demands bindings only for the inputs the program reads*, below). Whether an input may be absent is read off its declared type's shape, and off nothing else: `String?` — and `String | Number?` in either member order, since a union with an absence-admitting member admits absence — takes an absent or absence-reading value as `None`, while a shape requiring presence refuses it. The boundary is the one runtime type check that survives compilation, by design.
- Definition-cycle detection: the compiler's descent through the definitions carries the chain of names it is inside and refuses the moment one reappears on it — `Cyclic symbol definition: a → b → a.`, located at the reference that closed the cycle — so self- and mutual definition cycles are compile diagnostics, and since invocation lives only on `Program`, a cyclic program is unrunnable, not merely diagnosed. Only definitions the expression reads are ever descended into, so a broken definition nothing references cannot hold an unrelated expression's compile hostage.
- The totality harness and the admission-honesty law: for every rule of the composed dialect, every certified pair of a curated **specimen family** (types covering every shape constructor, each with edge values) must evaluate without escaping, into the resolved return type; for every `Type`, `coerce` output must pass `assert` (census-enforced) — together the runtime trust chain of compile-then-trust. The harness is evidence, not proof: extensions add specimens for every type their rules mention and re-run the sweep. The shape-soundness census keeps its specimen (C1) and shape-truth (C2) laws.
- RFC 0002: Locating compilation failures (`docs/rfc/0002-locating-compilation-failures.md`) — the design record for the failure channel's node location.
- **Failures say which node.** `TypeMismatch` gains `?string $path`: where the refusal was made, in the same `$`-rooted language `CompilationAnalysis` uses on the success path. `(name + 1) * 2` with `name` declared `String` now returns `[+] expects Number and Number; got String and 1.` at `$.children[0].node` — the inner `+`, and the same string the analysis gives that node when the tree compiles, so one addressing scheme serves both channels and prefixes give the ancestor chain. The path names the deepest node that refused; refusals a compiler wraps with `within()` carry one path per level. It is `null` when the verdict is not about a node — a cause like `String is not assignable to Number.` is a claim about types, produced by a relation that was given two types and cannot know which node made either. Previously the only way to attribute a failure was to compile every complete subtree and see which ones failed: 4.3× one root compile on a 13-node tree, with per-node types reconstructed rather than read. `compile()` still returns `Result<Program, TypeMismatch>` and `describe()` renders as before; the new parameter is trailing and optional, so every existing construction site and host is unaffected.
- **`??`, the authored default for an absent value.** Ordering rows are strict in present numbers, so `roof_percentage > 0.25` over an optional symbol resolves lifted and types `Boolean?` — which a seam requiring a definite verdict rightly refuses (`Boolean? is not assignable to Boolean: the value may be absent and the target does not admit null`). The ways out were both wrong: `Coerce` is a *presence claim* and errs at evaluation on a question nobody answered, and `x + 0` arithmetic hides the assumption in a sum. `(roof_percentage ?? 0) > 0.25` types `Boolean` and answers `false` for an unanswered question, with the assumption stored in the expression the author wrote. `T? ?? T` is `T`; `T? ?? T?` is `T?`, so `a ?? b ?? 0` ends definite exactly when its last arm is. The fallback must be assignable to the left's present type — `Option<'micro'|'small'> ?? 'other'` is refused rather than widening the result. A fallback that can never fire (a present left) or can never help (a `null` fallback) is a `DeadOperation`, the same refusal equality gives a comparison that can never hold, so `??` appears only where absence is real. Like `x == null`, the rule reads optional operands deliberately and matches before the resolver's lift pass — lifting would strip the very optionality it exists to discharge. Evaluation is total: no new error channel, though unlike PHP's `??` it does not short-circuit — an infix node evaluates both children before applying the operation, so a fallback that errs or costs does so even when the left operand is present. The core `Dialect` gains one rule and no existing expression changes meaning; the `DefaultValue` source node is unchanged and remains the spelling for a fallback that is data rather than an expression (it *coerces* its fallback, and is silently the identity on a source that can never be absent).
- **Operator enumeration**: `BinaryOperatorResolver::symbols()` and `UnaryOperatorResolver::symbols()` list every operator symbol a rule claims — the enumerating face of `resolve()`, which only ever answers a question about a symbol you already named. `Dialect::core()->operators()->symbols()` is `['!=', '!==', '&&', '*', '+', '-', '/', '<', '<=', '=', '==', '===', '>', '>=', '??', 'has', 'in', 'intersects', 'xor', '||']`, and an extension's operators join that list without the caller being taught about the extension. `extensions()` maps each symbol to the distinct extension identifiers that claim it (`'unattributed'` for rules registered without provenance), so a caller can group or badge by owner. Both are sorted: composition carries no precedence, so an order derived from registration would be an accident to depend on.

### Changed
- **The boundary demands bindings only for the inputs the program reads.** A call had to satisfy every non-`Option` declaration, read or not, so a host sharing one declaration scope across many small programs could never run any of them until the whole scope was filled: with `['name' => String, 'employees' => Number]` declared, a program whose source is just `name` refused `['name' => 'Ada']` with `required input [employees] is missing`. It now runs and answers `'Ada'`. The demand set is `Program::$references` — the compiler's own record of what the program reads, reaching through definitions — intersected with the non-`Option` declarations. A declaration the program never reads is ignored whether or not it is bound: no demand, no admission, no conversion attempt. Reads are settled at compile time and only a symbol node reads an admitted binding, so nothing evaluation does can observe an ignored name. What this entry changes is the demand set — reads only; how absence is ruled for the inputs that are demanded changes with it, in *Absence at the boundary is judged by the declared type's shape* below. The admission mechanics for a demanded input that is supplied are untouched under both `Boundary::Coerce` and `Boundary::Assert`: a bound value still passes through its declared type, a read bare input with no binding still refuses, and compile-time typing is unchanged — declarations still type the vocabulary, and reading an undeclared symbol is still a compile refusal. **Migration**: every call that worked before works now, with the same result. A host that leaned on the boundary to eagerly validate inputs its program does not read — declaring a hand-written contract wider than the expression and letting a call refuse on the unused part — loses that check and should validate that contract where it is stated.
- **A boundary refusal says which kind it is.** `BoundaryViolation` is now abstract over two cases a host reads differently: `MissingRequiredInput` (a required read was not supplied, and everything supplied was admissible) and `InadmissibleBinding` (a supplied value does not inhabit its declared type, including one that reads as absent where presence is required). A host evaluating a condition against a partly-answered form treats the first as "not answerable yet" and the second as a fault, and the difference is now a class rather than a message to parse. A fault dominates absence: a call that both omits one required input and supplies another badly is an `InadmissibleBinding`. Both carry `$rejections` — one `RejectedBinding` per input at fault, each holding that input's name and the message about it, so the two can never be read out of step — with `$violations` the messages projected out of them. **Migration**: `instanceof BoundaryViolation` and `$violation->violations` are unchanged; only direct construction of `BoundaryViolation` (never a documented host operation — it is a value the boundary returns) is no longer possible.
- **Absence at the boundary is judged by the declared type's shape.** A declaration whose shape admits absence takes an absent input however the absence arrives — no binding, a `null`, or a supplied value that reads as absent — and one requiring presence refuses. Previously a value that *converted* to absence was refused whatever the declaration said, which let the verdict turn on how a union happened to convert: `['x' => '']` against `Union(String, Option<Number>)` refused with `binding [x] reads as missing, but (String | Number)? is required`, while the same binding against `Union(Option<Number>, String)` — the same type, members swapped — answered `Ok(None)`. Both now answer `Ok(None)`: both project the shape `(String | Number)?`, and a union with any absence-admitting member admits absence. Bare declarations are unaffected — `''` against `String` is still an `InadmissibleBinding` (a value was supplied and does not inhabit `String`), no binding at all is still a `MissingRequiredInput` — and optionality is not a licence for a fault: a value that cannot convert at all is inadmissible whether or not absence is allowed. **Migration**: calls that refused only because an absence-admitting declaration read as absent now succeed with `None`; every call that succeeded before is unchanged.
- **A dialect indexes its rules once.** `Dialect::operators()`, `unaryOperators()`, and `literals()` built a fresh resolver on every call — re-asserting and re-indexing every rule the dialect carries — and `Expression::compile()` calls all of them, so every compile paid for the rebuild. They now build on first call and hand out the same instance afterwards; a dialect derived with `with()` indexes its own, so value semantics are unchanged. Measured on the core dialect: a compile through a shared dialect drops from 46 µs to 39 µs, and a caller probing `$dialect->operators()->resolve(...)` per candidate operator drops from 8.0 µs to 2.8 µs a question — it used to pay for the whole index each time. The saving grows with the number of rules a dialect carries.

### Fixed
- **An optional field behind an optional owner is optional once.** `PresentType` peeled a single `Option` constructor, but member access on an optional owner wraps an already-optional field: `quote.premium` on an `Option<{premium: Option<Number>}>` is the type `Option<Option<Number>>`. Nesting collapses in the shape algebra, so it *described* as `Number?` and looked right, while the projection answered `Option<Number>` — still optional. Operators asking what they get when the value is present were told "possibly nothing": `!quote.accepted` was refused because the lift pass saw `Boolean?` where a `Boolean` was needed, and `quote.premium ?? 0` certified `Number?` for a value that can never be absent, so `(quote.premium ?? 0) > 0.25` typed `Boolean?` and a condition seam refused it — the exact refusal `??` exists to remove. The projection now peels every constructor, preferring to peel over reifying so a host's own `Type` survives (an `Option<Money>` still exposes the host's `MoneyType`, not the canonical stand-in for its shape). `DefaultValue` had its own inlined copy of the single peel and so certified `Number?` for `DefaultValue(quote.premium, 0)`; it asks `PresentType` now, so the two spellings of an authored default agree on what a nested option exposes. Runtime values were always correct; only the static claim was weaker than the truth.
- **Every child of a match is addressable.** An expression pattern's compiled child was recorded under the constant role `pattern.expression`, while its sibling in the same compiler used `arm.{index}.expression`. A role is how a caller tells one child from another, so a match with two expression-pattern arms reported one name twice and neither pattern could be addressed: `match n { 5 => 'five', 10 => 'ten', _ => 'other' }` gave `['subject', 'pattern.expression', 'arm.0.expression', 'pattern.expression', 'arm.1.expression', 'arm.2.expression']`. Patterns are now `arm.{index}.pattern`, so the six roles are six names. **Migration**: a consumer matching on the literal `'pattern.expression'` reads `arm.{index}.pattern` instead — paths (`$.children[1].node`) are unchanged.

### Changed (Breaking)
- **The compiler's walk is the one description of an expression's structure.** The reflective source-tree scan (`UnboundSymbols`, which walked public properties to collect symbols) and the pre-compilation definition-graph pass (`DefinitionGraph`) are deleted; every structural fact is now read off the compiler's own descent, which each source compiler already states by compiling its children. `Expression::parameters()` derives from that walk (via `diagnose()`): a declared input read only through a definition now counts — with `['gross' => turnover * rate]` defined, the expression `gross + 1` reports `['turnover', 'rate']` where the reflective scan reported `[]`, and those are exactly the bindings the call demands — and a symbol a host compiler resolves without persisting counts because resolution itself records it, so the guard that refused such symbols (`symbol dependencies belong in the persisted source tree`) is deleted with the scan it kept honest. Definition cycles are refused where the descent closes them (see *Definition-cycle detection*, above). **Migration**: `parameters()` changes in three observable ways. It is now relative to the dialect — a region the dialect cannot compile at all (a source class with no registered compiler) is never descended, so symbols under it no longer appear and the refusal explaining the smaller answer is in `diagnose()`'s diagnostics, where the reflective scan reported such symbols regardless; call it under the dialect the tree is meant to compile with. Names come back in first-read order rather than reflective property order. And it now costs a full `diagnose()` — for an already-compiled expression, `Program::$references` is the cheap answer, so a host listing free variables across a stored corpus should read it off the compiled programs instead. A host that used `DefinitionGraph` to health-check a definitions corpus compiles each definition as its own expression.
- **Evaluation presupposes a passed check.** `Expression` is a description, not a callable: `call()`/`__invoke` live only on the `Program` that `compile()` returns, so running an unchecked program is unrepresentable. The value-directed runtime dispatch that double-checked every operator (`supportsOverloading` walking an ordered stack per evaluation) is deleted with its cause — overload resolution happens once, at compile time, on types. **Migration**: `$expression($bindings)` becomes `$expression->compile()->unwrap()($bindings)`; compile once at authoring/deploy time and invoke per request.
- **The runtime resolver layer is deleted.** `Resolvers/*` (including `DelegatingResolver` and its class map), `Patterns/*` (`PatternMatcher` and the matcher registry), and the per-call `Context` are gone — nodes compile to their evaluations, and the `illuminate/container`/`psr/container` dependencies fall away. `Expression` loses its `$resolver` constructor parameter. First-party node semantics are no longer host-swappable: the compiler certifies semantics, so silently replacing them was a drift channel, not a feature. Custom source behavior moves to compile-time `Extension::sourceCompilers()` callbacks (replacing both `TypedSource::returnType()` and the separately registered runtime resolver) so dependency injection survives without putting services into persisted source trees.
- **The operator contract collapses.** `supportsOverloading`/`evaluate`/`handles`/`typeOf` (four methods, two faces) become operator-owned `resolve()` verdicts. `OperatorOverloader`, `UnaryOverloader`, `BinaryOverloader`, `ComparisonOverloader`, `LogicalOverloader`, `NotOverloader`, `NegateOverloader`, and `DefaultOverloader` no longer exist — their semantics live in core dialect rows and `Equality`. `NullOverloader` (the `null ∘ null → null` rule) is deleted outright: it deliberately certified nothing, which under compile-then-trust means it could never run; binary absence policy is spelled as a rule that resolves `Option`-shaped operand types and refuses present pairs. **Migration**: signature-built extension rules are unchanged; hand-written rules implement `BinaryOperatorRule` or `UnaryOperatorRule`, own one symbol, and return an explicit resolution variant (see the extension guide).
- **`Unknown` is inert.** The "sanctioned unsoundness" hole is closed: `admits()` refuses `Unknown` operands, and operators, comparisons, and member access on `Unknown` are compile errors pointing at the fix — bridge with `Coerce` (convert a representation) or `Ascription` (claim a membership, runtime-verified). Gradualness is syntax the author can see, not checker leniency; every runtime type check in the system is admission through a `Type`'s two faces, at three visible sites: the binding boundary, `Coerce`, `Ascription`.
- **Runtime honesty** — the program does only what the compiler certified:
  - `StringType::assert` no longer reads `''` or `'null'` as absence — they are ordinary strings. The absence readings remain in `coerce`, the lenient admission face.
  - `DictType`: `[]` is a dict in **both** faces (`coerce([])` yields `Some([])`, not an absence reading — hosts that want "empty reads as missing" declare `Option<Dict<T>>`), and non-empty lists are rejected in both faces (previously `coerce([1, 2])` returned `[1, 2]`, a value the type's own `assert` refuses).
  - `ListType::assert` is strict membership: associative arrays are rejected instead of silently reindexed (reindexing remains in `coerce`); `ListType`/`ListShape` reject impossible bounds at construction (`min >= 0`, `max >= min`).
  - `BooleanType::coerce(null)` now yields absence (`None`) instead of silently producing `false`, so required-but-missing boolean bindings are detectable.
  - `!`/`not` are boolean-only — PHP truthiness on non-booleans no longer evaluates (it no longer compiles).
  - A match where no arm matches is a runtime error instead of silently evaluating to absence — and unprovable exhaustiveness is a compile error, so add a wildcard arm for a deliberate default.
- **Equality is value equality**, never PHP juggling: numeric within `Number` (`1 == 1.0`), strict identity otherwise, element-wise for containers, `false` across bases (`5 == '5'` is now `false`); `===`/`!==` are aliases of `==`/`!=`. The set operators (`has`/`in`/`intersects`) and literal patterns use the same one definition, so `match 5 { 5.0 => … }` matches exactly as exhaustiveness coverage predicts (`true in [1]` is now `false`). `ValueEquality` is the **one equality authority** — `Type::compare` is deleted: it defined a second, disagreeing equality (strict identity, so `1 === 1.0` was false) that nothing in the engine consumed.
- **Operators own only what they resolve**: equality for scalars, `null`, and (nested) arrays of them — never objects (object equality belongs to the type's owner, now expressible as an ordinary extension row) and never `Unknown`; ordering and arithmetic for real numbers only (numeric strings refused); set-operator needles judged universally over unions, opaques refused. String ordering and object comparison are compile errors, not silently evaluated PHP semantics.
- **Symbols are exact keys; member access is structure.** A namespaced symbol (`SymbolSource('turnover', 'customer')`) is answered by a binding or definition named exactly `customer.turnover` — never by digging into the value of a `customer` binding (`Bindings`' associative-array flattening and its descent successor are both gone; `TypeEnvironment` mirrors the same rule). Reaching into a record value is `MemberAccessSource`, certified against declared record fields. Caller data is therefore structurally unable to answer for — or shadow — a definition. **Migration**: bind keys exactly as declared (`['quote.turnover' => 600000]`, not `['quote' => ['turnover' => 600000]]`), or declare `quote` as a record, bind it whole, and use member access.
- **Records are exact** — no open/closed distinction: a record's value set is fully described by its declared fields (that exactness is what makes whole-record equality certifiable). The admission faces divide the work: `assert` rejects undeclared keys (strict membership), `coerce` takes the declared slice of wide input — hosts still pass whole context rows and only declared fields enter. Data with unenumerable keys is a `Dict`.
- **Declarations and definitions are disjoint namespaces**: a symbol is a parameter or a derived value, never both — a collision is a constructor error. Together with stripping and exact-key lookup, shadowing a definition is unrepresentable. Callers that overrode derived values via bindings model the override in-language: an `Option`-typed parameter the definition consults. Callers that relied on undeclared bindings feeding free symbols declare them (worst case `Unknown` — the explicit gradual path, bridged where used).
- **`TypeDefinition` is split into `Coerce` and `Ascription`**: `Coerce` converts via `coerce()` and types verbatim (the statically opaque conversion bridge); `Ascription` verifies via `assert()` and is checked at compile time (`Unknown`-or-overlaps — a disjoint claim is a compile error). **Absence cannot cross either node non-optionally**: when the declared/claimed type is not Option-shaped and the value reads as missing, evaluation errs naming the requirement instead of passing a silent `None` — declare/claim `Option<T>` where absence is legal.
- One representation of null in the resolution channel: a bound `null` normalizes to absence at symbol lookup (presence still lives in `has()`), and the admission bridges normalize an optional `Some(null)` the same way.
